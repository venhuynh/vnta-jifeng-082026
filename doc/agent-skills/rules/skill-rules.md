# Skill Rules

Use these rules when writing or updating skills for this repo.

## Writing Rules

- Use lowercase hyphenated folder names
- Keep `SKILL.md` as the primary entry point
- Put long details in `references/`
- Avoid extra docs unless they change behavior

## Quality Rules

- Prefer process over general advice
- Prefer specific commands over vague instructions
- Add verification steps that must be checked
- Include clear triggers in the frontmatter description

## Review Rules

- Check correctness first
- Then readability
- Then architecture
- Then security
- Then performance
